# 실무형 과제 작업 시트

작업할 과제 폴더에 복사하고 실제로 확인한 내용을 채우세요. 짧은 모의시험에서는 합의문, 검증 두 줄, 인수인계 한 단락이면 시작할 수 있습니다.

## 실무자와의 합의

- 사용자와 최근 사건:
- 현재 사람이 따르는 단계와 실패 비용:
- 신뢰할 입력 원천과 최종 판단자:
- 이번 버전이 바꿀 결정 하나:
- 기준값 / 목표값 / 같은 조건으로 재는 방법:
- 대표 입력 / 기대 출력 / UI에서 볼 증거:
- 합의한 범위와 나중에 할 일:
- 답변이나 데이터가 충돌할 때 우선순위:
- 확인받은 답변과 후속 질문:

## 인수인계 · 60초 읽기

- 현재 사용자 목표와 합의한 조건:
- 진입점 / 마지막 변경 파일·함수 / 커밋 또는 diff:
- 실행 환경 / 처음 돌릴 명령:
- 마지막 검증과 실제 결과:
- 의도적으로 남긴 부분과 사용자 영향:
- 다음 작업 하나 / 끝났다고 볼 때의 입력과 출력:

## 제출 직전

- [ ] 안내에 맞는 파일과 커밋 상태를 확인했다.
- [ ] 시작 순서를 새 터미널에서 재현했다.
- [ ] 결과의 근거를 코드나 실행 로그로 가리킬 수 있다.
- [ ] 남은 한계와 다음 검증을 적었다.

## 사후 확인 답변 양식

결론 한 문장 → 내가 수정한 코드에서 값이 변하는 위치 → 실제로 돌린 입력과 결과 → 실패할 수 있는 조건과 다음 검사.

예시. “후보 빌드의 상충 보고는 검토 필요로 표시합니다. [함수]에서 [키]로 묶은 뒤 동일한 관측 시각의 상태를 대조합니다. [명령]에 R-005·R-006을 넣었을 때 [실제로 본 출력]을 확인했습니다. 누락된 관측 시각에 대해서도 안전한지 [추가 입력]으로 검증하겠습니다.”
