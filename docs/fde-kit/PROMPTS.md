# FDE 단계별 프롬프트

대괄호는 현재 과제의 증거로 바꿔 사용하세요. 실제 응시에서 허용되는 채팅, 프롬프트와 외부 자료는 안내를 확인하세요.

## 1. 실무자 발견 인터뷰

~~~text
최근 비슷한 문제가 실제로 생긴 사례 한 건을 처음부터 끝까지 알려주실 수 있나요?
누가 어떤 데이터를 보고 어떤 결정을 내려야 했고, 어디에서 시간이 더 걸렸나요?
그때 사용한 문서나 기록 중 최종 판단의 근거는 무엇이었나요?
같은 입력으로 시연했을 때 무엇이 보이면 이번 도구가 도움이 되었다고 판단하시겠어요?
~~~

## 2. 실무자에게 합의문 확인

~~~text
제가 이해한 이번 목표는 [사용자]가 [상황]에서 [결정]을 하도록 돕는 것입니다.
현재 [기준값]이고, [동일한 입력과 측정 방법]으로 [목표]를 확인하겠습니다.
첫 버전은 [사용자 경로]를 구현합니다. [누락·충돌 상태]는 [처리 방식]으로 보여주겠습니다.
판정이 어려운 지점은 [질문 하나]입니다. 이 기준으로 진행해도 될까요?
~~~

## 3. AI에게 첫 변경의 범위 지정

~~~text
[합의 내용]과 현재 README, [관련 파일]을 읽어줘.
첫 기능은 [샘플 입력 → 판정 → 화면에서 확인할 근거] 경로 하나야.
기존 실행 명령을 먼저 확인하고, 구현할 파일과 내 이해를 바꾸는 모호한 요구가 있으면 짚어줘.
[입력]으로 [직접 계산한 기대 결과]가 나와야 해.
이 범위에서 구현하고 실행 명령과 실제 관찰 결과를 알려줘.
~~~

## 4. 재현과 독립 검증

~~~text
[실행 명령과 환경]에서 [입력]의 실제 결과가 [관찰값]이야. 명세에 따른 기대값은 [기대값]이야.
같은 입력으로 먼저 실패를 확인하고, 처음 값이 달라지는 위치를 찾아줘.
원인에 해당하는 범위만 수정하고 같은 명령으로 다시 확인해줘.
추가로 [정상 케이스]도 돌려 변경 영향과 실제 출력을 알려줘.
~~~

## 5. 실무자 수용 확인

~~~text
[대표 입력]으로 실행해 [화면 경로]에서 [판정]과 근거 [기록 ID]를 확인할 수 있습니다.
[실패 입력]에서는 [관찰값]이 나왔습니다. 이 정보로 [업무 결정]이 가능한지 확인해 주실 수 있나요?
실제로 사용하시기 전에 가장 먼저 확인해야 할 사례 한 가지가 있다면 무엇인가요?
~~~

## 6. 새 세션 인수인계 작성

~~~text
합의 내용과 현재 변경, 실제 검증 결과를 읽고 다음 세션이 60초 안에 이어받을 글을 작성해줘.
사용자 목표, 현재 동작, 실제 파일과 함수, 실행 명령·관찰값, 남은 위험, 다음 작업 하나를 적어줘.
확인한 사실과 가정은 각각 표시하고, 다음 작업의 종료 조건을 입력과 기대 출력으로 작성해줘.
~~~

## 7. 새 세션에서 재현하기

~~~text
[인수인계 내용]을 읽고 README와 현재 변경분을 대조해줘.
기록된 첫 실행 명령을 실제로 실행하고 결과 차이가 있는지 확인해줘.
다음 작업은 [하나]야. 개선하기 전에 필요한 확인이 있으면 명령과 이유를 먼저 알려줘.
~~~

## 8. 사후 확인 질문 준비

~~~text
[실제 변경·검증 기록]을 바탕으로 3분 안에 직접 답할 질문 5개를 만들어줘.
구조와 근거, 경계 입력, AI 제안을 바꾼 이유, 실패의 영향, 새 세션이 재현할 검사에 대해 물어봐.
각 질문은 내가 제출한 코드나 실행 기록 한 곳을 확인해야 답할 수 있게 해줘.
질문만 보여줘. 내 답변을 나중에 주면 코드 위치, 관찰, 영향, 다음 검증의 근거가 있는지 짚어줘.
~~~
